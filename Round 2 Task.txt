Country → University/College → Program/Degree → Transcript Keywords → Search Variations → Result Pages

Important Transcript Requirement

The main usable transcript dataset should contain records showing at least 2 completed academic years.

The automation should inspect the transcript/academic record wherever enough information is available and classify it into one of these categories:

2 Years or More — Main Dataset
Transcripts showing at least 2 completed academic years should go into the main accepted dataset.

Less Than 2 Years — Separate Dataset
Any relevant transcript showing less than 2 completed academic years should still be collected, but it must be placed separately and should not be mixed with the main dataset.

If the duration cannot be confidently determined, mark it as Needs Review / Duration Unclear rather than guessing.

Most Important Technical Requirement — Reusable AI Browser Agent

Do not build this as a one-time Scribd script.

We want a general-purpose AI-powered Chrome automation agent that can later be used for many different browser automation tasks.

Ideally, it should work like a Chrome extension or single installable package/file.

The idea is:

Install it on a computer → open Chrome → give it a command → the agent understands the task and starts operating the browser.

For example, in the future we may give it instructions such as:

“Go to this website, understand how it works, search for this type of information, organize the results and export them.”

The core automation should be reusable without rewriting the whole program every time.

It should be easy to install on another Windows/Mac system and start using with minimal setup.

Open-Source AI Requirement

For the heavy day-to-day browser automation, the system should use open-source/local AI wherever practical, so the company is not paying OpenAI/Claude API credits for every browser action.

You can use paid tools such as Codex or Claude while building/debugging the system, but the finished automation should be designed so routine operation can run primarily using:

* Local/open-source LLMs
* Open-source browser automation
* Local decision-making/classification where practical

We want to avoid a system where thousands of browser actions continuously consume paid AI API credits.
