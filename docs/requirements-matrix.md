| **Minimum Record Schema** | "It should collect and organize at minimum: Country, College/University, Document Title, Education Level, Program, if available, Document Type, Academic Duration / Years Completed, Classification: 2+ Years / Less Than 2 Years / Needs Review, Scribd Link, Document ID, Status" | **CONFIRMED** | PostgreSQL schema and TypeScript Zod domain schema strictly enforcing all 11 fields, with validation and non-null constraints where appropriate. | Schema validation test fixtures; database migration tests; JSON schema output contract tests. |
| **2+ Years Completed Rule (Main Dataset)** | "2 Years or More — Main Dataset: Transcripts showing at least 2 completed academic years should go into the main accepted dataset." | **CONFIRMED** | Classification engine (deterministic regex + local LLM analyzer) evaluates academic progression indicators (e.g. Years 1 & 2, Semesters 1–4, Part I & II, Level 100–200+, credit thresholds $\ge 60$) and tags record as `ACCEPTED_2_YEARS_OR_MORE`. | Classification unit tests with synthetic and real transcript text samples verifying accurate 2+ year identification. |
| **Less Than 2 Years Rule (Separate Dataset)** | "Less Than 2 Years — Separate Dataset: Any relevant transcript showing less than 2 completed academic years should still be collected, but it must be placed separately and should not be mixed with the main dataset." | **CONFIRMED** | Classifier assigns `LESS_THAN_2_YEARS` for single-semester, single-year, or incomplete records; export engine routes these records to a dedicated dataset/directory. | Unit test cases for 1-year diplomas, single-semester grade cards ensuring they are routed exclusively to the separate dataset. |
| **Needs Review / Duration Unclear Rule** | "If the duration cannot be confidently determined, mark it as Needs Review / Duration Unclear rather than guessing." | **CONFIRMED** | Strict confidence scoring: records lacking explicit progression/duration markers or falling below confidence threshold are marked `NEEDS_REVIEW` instead of making speculative guesses. | Test suite containing ambiguous transcript text fixtures verifying deterministic fallback to `NEEDS_REVIEW`. |
| **Country-Wise Organization** | "After collection, the automation must automatically organize the transcripts country by country... | **Thoroughness & Deep Pagination** | "This is not only a demo. Management will check the actual output, so the system should search as thoroughly as possible and should not stop after basic searches or the first few pages." | **CONFIRMED** | Browser automation engine supports cursor-based and infinite-scroll pagination traversal up to exhaustive completion or site pagination limits, logging depth and exhaustion status. | End-to-end pagination mock tests verifying traversal beyond initial pages until termination conditions are reached. |
| **Deduplication & Document ID Tracking** | "It must automatically remove duplicates and remember what has already been searched." | **CONFIRMED** | Database uniqueness constraints on `(source, document_id)` and content hash indexing; search deduplication cache in Redis/PostgreSQL. | Deduplication tests verifying duplicate ingestion attempts increment duplicate counters and bypass re-processing. |
| **3 Additional Free / Public Sources** | "You also need to independently find 3 additional websites similar to Scribd where comparable academic transcript/academic-record data is legally available for free... use the same automation framework to extract relevant public data from them." | **CONFIRMED** | Extensible `BaseSourceAdapter` interface implemented for 3 verified public repositories (e.g. Internet Archive `archive.org`, CORE, Zenodo / Studocu public docs) conforming to the unified schema. | Adapter contract test suite executed against mock responses and public fixture data for each source. |
| **Reusable AI Browser Agent Architecture** | "Do not build this as a one-time Scribd script. | **Local / Open-Source AI (Zero API Cost)** | "For the heavy day-to-day browser automation, the system should use open-source/local AI wherever practical, so the company is not paying OpenAI/Claude API credits for every browser action... | **Non-Bypass & Authorized Access Rule** | "The automation must operate only through access we are authorized to use and should not attempt to bypass CAPTCHAs, security systems, paid-access controls or other website protections." | **CONFIRMED** | Explicit authorization boundary: uses provided employer credentials via authenticated Chrome session, halts/alerts upon encountering CAPTCHAs or paid barriers, and does not include circumvention tooling. | Security boundary audit test verifying abort handlers trigger on HTTP 403, 429, or CAPTCHA challenge detection. |
